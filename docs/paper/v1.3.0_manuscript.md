## Abstract

Domain-specific languages (DSLs) for Monte Carlo simulation simplify model specification, static verification, and code generation, yet typically rely on fixed batch sizes and static multiprocessing configurations at runtime. A systematic audit of our baseline compiler (`montecarlo-dsl` v1.2.0) exposed three structural limitations: (1) deriving random-number substreams from physical batch indices (`SeedSequence([MASTER_SEED, batch_index])`) coupled the numerical realization to the physical batch size, breaking bitwise reproducibility whenever batch granularity changed; (2) retaining raw sample chunks (`all_chunks`) and uncompacted per-block correlation dictionaries incurred $O(N)$ coordinator memory growth and $O(B \cdot N)$ aggregation overhead; and (3) unconditionally spawning worker pools degraded execution latency and duplicated resident process memory whenever inter-process coordination dominated numerical computation.

In this paper, we present an adaptive execution planning architecture (`montecarlo-dsl` v1.3.0) that combines a four-parameter linear cost prior over interpretable composite structural indices of the Abstract Syntax Tree (AST)—calibrated via exact KKT-constrained Ridge regression and propagated directly to the runtime scheduler—with an online, zero-waste pilot block measurement via sample-size-weighted shrinkage to select concurrency levels and physical task groupings while strictly preserving canonical numerical reproducibility across physical schedules. We decouple *logical blocks*—which govern counter-based `Philox` random streams indexed by `(MASTER_SEED, logical_block_index, var_index)` and deterministic Chan–Golub–LeVeque reductions—from *physical tasks* scheduled across workers, maintaining separate accumulators for live physical-task progress events and canonical logical-block completion. Furthermore, we introduce a unified contiguous-frontier equal-mass centroid sketch compaction mechanism (`BoundedStreamingHistogram`) and Neumaier-compensated paired correlation reduction that bound retained coordinator payload memory to $O(K_{\max}) = O(1)$ with respect to total iterations $N$. Across 6 stochastic models and 14 physical scheduling configurations at $N = 10^6$ iterations, our runtime produces a single canonical SHA-256 result hash per model, reduces retained coordinator payload memory by 97.8%–99.0% at $N = 2.5 \times 10^6$ (while avoiding 48.1%–51.8% of sum of per-process peak RSS when in-process execution is selected), bounds weighted quantile relative error to $\le 0.174\%$ across 6 distribution families and 10 branches (including multimodal, right-skewed, discrete, heavy-tailed, and paired $\pm$ branches), achieves 2.41x–5.17x end-to-end speedups at $N = 10^6$ (and 2.72x–5.70x at $N = 10^5$) over the frozen v1.2.0 baseline, and delivers 1.20x–1.80x speedups over fixed v1.3.0 scheduling in a 10-repetition $4 \times 2$ ablation study.

## 1. Introduction

Monte Carlo methods are fundamental across quantitative finance, reliability engineering, uncertainty quantification, and operational research (Giles, 2015). Writing ad hoc simulation scripts in general-purpose languages often leads to recurring defects: unvalidated probability distributions, silent propagation of `NaN` or infinite values, unquantified Monte Carlo standard errors (MCSE), and fragile random-number seeding that breaks reproducibility when parallelized.

Domain-specific languages address these issues by raising the level of abstraction. A declarative specification allows the compiler to verify domain invariants statically and synthesize vectorized execution code automatically. However, translating a high-level stochastic model into an efficient parallel execution plan introduces a tension between **dynamic runtime optimization** and **exact numerical reproducibility**:

1. **The Concurrency Overhead Trap**: Vectorized numerical kernels in NumPy execute simple expressions in a few hundred nanoseconds per sample. Spawning worker processes via `ProcessPoolExecutor` and serializing arrays across inter-process communication (IPC) pipes introduces tens to hundreds of milliseconds of overhead. As observed in our v1.2.0 baseline campaign (`docs/baseline_v1.2.0_audit.md`), statically assigning 2 or 4 workers to lightweight or medium-sized workloads consistently slowed down execution and nearly doubled aggregate resident memory (RSS) compared to single-process execution.
2. **The Schedule–Reproducibility Coupling Problem**: To adapt batch sizes and worker counts dynamically to model complexity and host resources, the runtime scheduler must be free to group or split work into variable-sized physical tasks. In conventional parallel Monte Carlo implementations that seed pseudo-random number generators (PRNGs) per physical task or batch index, changing the physical task size changes how many variates are drawn from each substream, altering the simulated sample path and invalidating exact reproducibility. Moreover, floating-point addition is non-associative, so out-of-order parallel reductions introduce run-to-run variation unless reduced in a canonical order (Demmel & Nguyen, 2013; Collange et al., 2015).
3. **The Streaming Memory and Progress Consistency Bottleneck**: Reporting live histograms and empirical quantiles (`p05`, `p50`, `p95`) alongside moment estimators across millions of iterations naively requires retaining all generated samples in memory ($O(N)$ space). Furthermore, when logical blocks are decoupled from physical tasks, progress events emitted per completed physical task must reflect only completed physical tasks without polluting the canonical logical-block reduction.

### 1.1. Research Questions

To investigate this gap systematically, we formulate four explicit research questions:

- **RQ1 (Schedule-Independent Numerical Reproducibility):** *Can a Monte Carlo DSL runtime decouple logical sample identity from physical task scheduling—via counter-based PRNG streams, dual progress/canonical accumulators, and canonical logical-block reduction—so that the canonical final numerical output remains bitwise identical (SHA-256 invariant) across changes in worker count, physical batch size, scheduler policy, and task completion order while keeping every intermediate batch progress event consistent?*
- **RQ2 (AST Cost Prior and Pilot Calibration Generalization):** *To what extent does a parsimonious four-parameter linear cost model over interpretable composite structural indices of the AST, fitted via exact KKT-constrained Ridge regression and combined at runtime with an online in-process pilot block via sample-size-weighted shrinkage, accurately predict per-sample execution cost on unseen stochastic models?*
- **RQ3 (Adaptive Scheduling Performance and Component Ablation):** *When the trained cost model is integrated into the compiler and runtime scheduler, under what workload sizes and model complexities does the AST-and-pilot-guided adaptive scheduler reduce execution time and OS resident memory relative to both the frozen v1.2.0 baseline and fixed v1.3.0 scheduling, and what is the isolated contribution of each scheduling source (`ast_only`, `pilot_only`, `hybrid`) and of IEEE-754-safe AST optimization?*
- **RQ4 (Asymptotically Bounded $O(1)$ Coordinator Memory vs. Statistical Fidelity):** *Can contiguous-frontier equal-mass centroid sketch compaction and compensated correlation folding bound retained coordinator payload memory to $O(1)$ with respect to total iterations $N$ (both in-process and under multiprocessing) while preserving exact moments, extrema, paired correlations, and sample counts, and what is the empirical approximation error on weighted quantiles (`p05`, `p50`, `p95`) across unimodal, multimodal, skewed, discrete, heavy-tailed, and paired $\pm$ distributions?*

### 1.2. Summary of Contributions

1. **Schedule-Independent Reproducibility and Dual Progress/Canonical Accumulation (Component C)**: A formal separation between canonical *logical blocks* (`logical_block_size` $L$) and *physical tasks*, combining counter-based `Philox` streams indexed by `(MASTER_SEED, logical_block_index, var_index)` with a dual-state coordinator that maintains exact invariants on intermediate physical-task `batch` events while reducing completed logical blocks in strictly canonical index order for the terminal `complete` event.
2. **Composite Structural AST Cost Model + Zero-Waste Pilot Shrinkage Integrated into the Runtime (Component A)**: A four-parameter linear cost model over interpretable composite structural indices extracted from the validated AST, fitted via exact active-set KKT-constrained Ridge regression, propagated through `compile_source()` and `server.py` into the generated runtime, and calibrated online using logical block $b = 0$ as an in-process pilot execution without discarding a single simulated sample.
3. **Unified Cost-Aware Adaptive Scheduler and IEEE-754 Safe AST Optimizer (Component B & Auxiliary Compiler Pass)**: A unified `AdaptiveMonteCarloScheduler` that selects between in-process serial execution (avoiding concurrency and IPC overhead) and guided multiprocessing tasks under a memory budget, paired with a differential-tested AST optimizer that respects `NaN`/`Inf` discard semantics.
4. **Unified Contiguous-Frontier $O(1)$ Streaming Histogram, Equal-Mass Centroid Quantiles, and $O(1)$ Paired Correlation Folding**: A unified `BoundedStreamingHistogram` shared between `statistics.py` and `generator.py` that compacts completed logical blocks into a fixed-capacity equal-mass centroid sketch (`MAX_GLOBAL_SKETCH_POINTS = 2048`) and folds paired branch correlations in $O(1)$ space via Neumaier compensated summation, accompanied by dual instrumentation of retained coordinator payload memory and OS process/worker peak RSS.
5. **Comprehensive Reproducible Evaluation**: A 10-part experimental campaign (30-repetition confirmatory benchmarks, 25-seed analytical validation, 14-schedule SHA-256 invariance tests, out-of-sample cost generalization across 14 models with design-matrix conditioning diagnostics, quantile/histogram fidelity across 6 distribution families and 10 branches, in-process and multiprocessing RSS profiling, and a $4 \times 2$ ablation study), backed by 229 passing automated tests.

## 2. Related Work and Scientific Gap

Our work builds upon five research threads in scientific DSLs, parallel random number generation, deterministic parallel reductions, streaming quantile sketches, and adaptive simulation scheduling.

### 2.1. Domain-Specific Languages for Scientific Simulation and Cost-Guided Scheduling

**PPME (Karol et al., 2018)** introduced a domain-specific language and integrated editor for parallel particle methods, demonstrating how a formal metamodel, type inference, static diagnostics, and code generation can be combined with parallel scientific libraries. **STELLA (Mohr & Stefanovic, 2016)** presented a Python-based DSL for simulations that compiles declarative models into specialized high-performance code, evaluating execution times against reference implementations and verifying functional equivalence. More recently, **SimDSL (Tasnim & Zhao, 2026)** introduced an embedded Python DSL for large-scale GPU-resident Entity Component System (ECS) and dense-array simulations (`https://doi.org/10.3390/software5030037`), compiling high-level queries and systems into staged execution plans. In image processing and tensor compilers, **Halide (Adams et al., 2019)** demonstrated the effectiveness of combining structural feature extraction with learned cost models to guide scheduling decisions.

As summarized in Table 1, existing simulation DSLs establish that static analysis, AST transformations, and specialized code generation are mature techniques. However, prior simulation DSLs do not address the three-way interaction in stochastic Monte Carlo workloads between (i) dynamic task resizing to avoid multiprocessing IPC overhead, (ii) schedule-independent PRNG and floating-point reduction invariance across paired branches ($\pm$) and runtime domain discards (`NaN`/`Inf`), and (iii) $O(1)$ bounded coordinator memory for streaming histograms and quantiles.

### 2.2. Parallel Pseudo-Random Number Generation and Deterministic Reductions

Generating independent random streams across parallel workers is a classic problem in stochastic simulation. **Salmon et al. (2011)** introduced counter-based PRNGs—specifically **Philox** and **Threefry**—which compute $X_n = f_K(n)$ by applying a cryptographic bijection $f_K$ to an integer counter $n$. Unlike linear congruential or Twisted GFSR generators that require jump-ahead polynomials, counter-based generators allow $O(1)$ random access to arbitrary substreams via key/counter tuples. We build directly upon NumPy's implementation of `Philox` and `SeedSequence`, mapping the counter hierarchy to `(MASTER_SEED, logical_block_index, var_index)` so that physical task coalescing never alters stream assignment.

Even with identical random draws, asynchronous parallel reductions can yield non-reproducible floating-point results because IEEE-754 addition is non-associative. **Demmel and Nguyen (2013)**, **Arteaga et al. (2014)**, and **Collange et al. (2015)** showed that bit-reproducible parallel reductions require either fixed reduction trees indexed by logical data blocks or exact/compensated accumulators. Single-pass calculation of sample variance also requires numerically stable recurrences: **Welford (1962)** formulated an incremental recurrence for running mean and sum of squared deviations ($M_2$), and **Chan, Golub, and LeVeque (1983)** generalized this to pairwise block reductions. Our coordinator combines Chan–Golub–LeVeque block summaries with a strictly increasing contiguous-frontier reduction over logical block indices $b = 0, 1, \dots, B-1$ and Neumaier (1974) compensated summation for paired correlations.

### 2.3. Streaming Quantile Sketches and Sequential Stopping Precautions

Computing exact order statistics (`p05`, `p50`, `p95`) in a single pass requires $\Omega(N)$ storage (Munro & Paterson, 1980). Consequently, streaming systems rely on bounded-space summary structures: **Greenwald and Khanna (2001)** introduced deterministic $\epsilon$-approximate quantile summaries in $O(\frac{1}{\epsilon}\log(\epsilon N))$ space; **Karnin, Lang, and Liberty (2016)** developed the randomized **KLL** sketch achieving optimal $O(\frac{1}{\epsilon}\sqrt{\log(1/\delta)})$ space; and **Dunning and Ertl (2019)** proposed the **t-digest**, which clusters sorted samples into weighted 1D centroids with exact boundary preservation. Inspired by centroid-based digestion and deterministic block merging, our `BoundedStreamingHistogram` summarizes each logical block of size $L$ into equal-mass centroids (preserving exact discrete atoms when unique support size $\le 256$ and exact block extrema with unit weight) and folds contiguous logical blocks into a bounded 2,048-centroid sketch in $O(1)$ memory.

Finally, in sequential Monte Carlo and Bayesian active learning (Kirsch et al., 2019), batch sizes are sometimes adapted alongside an optional stopping rule that halts execution when a 95% confidence interval half-width falls below $\epsilon$. As established in sequential analysis (Jennison & Turnbull, 1999; Howard et al., 2021), repeatedly testing a fixed-sample normal confidence interval $\bar{Y}_n \pm 1.96\,s_n/\sqrt{n}$ without alpha-spending or confidence-sequence corrections inflates Type I error and degrades coverage below 95%. Accordingly, our method adapts *only* the physical execution schedule while holding the user-declared sample size $N$ fixed.

## 3. System Architecture and Formal Algorithms

The `montecarlo-dsl` v1.3.0 compilation and execution pipeline consists of five static compiler stages (`LEX -> SYN -> SEM -> OPT -> COST/GEN`) followed by the adaptive runtime coordinator.

### 3.1. Four-Parameter AST Cost Model over Composite Structural Indices and Pilot Shrinkage (Component A)

Let $\mathcal{P}$ be a semantically validated DSL program with optimized AST $\mathcal{T}$. From $\mathcal{T}$, `extract_ast_cost_features` (`src/montecarlo_dsl/cost_model.py`) computes 11 primitive counts: random variable declarations by family ($N_{\text{unif}}, N_{\text{norm}}, N_{\text{disc}}$), total discrete support pairs ($S_{\text{disc}}$), arithmetic operations ($N_{\text{add}}, N_{\text{un}}, N_{\text{mul}}, N_{\text{div}}$), non-linear operations ($N_{\text{pow}}, N_{\text{sqrt}}$), branch multiplicity $B \in \{1, 2\}$ ($B = 2$ when $\mathcal{T}$ contains $\pm$), and quantile request indicator $\mathbb{I}_{\text{quant}} \in \{0, 1\}$.

To avoid overparameterization when calibrating against a benchmark suite of reference models, these primitive counts are projected onto **four interpretable composite structural indices**:

$$\begin{aligned}
I_{\text{dist}}(\mathcal{T}) &= 1.0\,N_{\text{unif}} + 2.0\,N_{\text{norm}} + 2.6\,N_{\text{disc}} + 0.35\,S_{\text{disc}} \\
I_{\text{arith}}(\mathcal{T}) &= B\,\bigl(0.35\,(N_{\text{add}} + N_{\text{un}}) + 0.40\,N_{\text{mul}} + 0.80\,N_{\text{div}}\bigr) + 2.8\,\mathbb{I}_{B=2} \\
I_{\text{trans}}(\mathcal{T}) &= B\,\bigl(1.80\,N_{\text{pow}} + 1.00\,N_{\text{sqrt}}\bigr) + 0.60\,\mathbb{I}_{\text{quant}}
\end{aligned}$$

where $2.8\,\mathbb{I}_{B=2}$ captures the paired branch difference ($\Delta = Y_+ - Y_-$) and Pearson correlation (`np.corrcoef`) overhead unique to $\pm$ models. The compact feature vector is $\psi(\mathcal{T}) = \bigl[1,\; I_{\text{dist}}(\mathcal{T}),\; I_{\text{arith}}(\mathcal{T}),\; I_{\text{trans}}(\mathcal{T})\bigr]^{\top} \in \mathbb{R}^4$, and the static per-sample cost prior is:

$$\hat{c}_{\text{AST}}(\mathcal{T}) = \theta^{\top} \psi(\mathcal{T}), \qquad \theta = (\theta_0, \theta_{\text{dist}}, \theta_{\text{arith}}, \theta_{\text{trans}})^{\top} \in \mathbb{R}_+^4$$

**Design-Matrix Conditioning and Exact KKT-Constrained Ridge Calibration:** These composite indices are structurally interpretable rather than mutually orthogonal, because complex stochastic models often combine arithmetic and non-linear operations. Across our $n_{\text{train}} = 8$ training models (`InterpretableASTCostModel.design_matrix_diagnostics`), the $8 \times 4$ design matrix $X$ has **full column rank $\text{rank}(X) = 4$**, an unstandardized condition number $\kappa(X) = 11.3601$, a standardized condition number $\kappa(X_{\text{std}}) = 3.4054$, and a Pearson correlation $r(I_{\text{arith}}, I_{\text{trans}}) = 0.8234$. To handle this collinearity and guarantee strictly positive physical cost weights, we calibrate $\theta$ via lower-bounded, prior-centered Ridge regression:

$$\hat{\theta} = \arg\min_{\theta \ge 0.25\theta_{\text{prior}}} \sum_{m=1}^{n_{\text{train}}} \bigl(\psi(\mathcal{T}_m)^{\top}\theta - y_m\bigr)^2 + \lambda_{\text{eff}} \left\| \frac{\theta - \theta_{\text{prior}}}{\theta_{\text{prior}}} \right\|_2^2, \qquad \lambda_{\text{eff}} = \lambda \cdot \frac{\text{tr}(X_{\text{scaled}}^{\top} X_{\text{scaled}})}{p}$$

where $X_{\text{scaled}} = X\,\text{diag}(\theta_{\text{prior}})$ and scaling $\lambda = 10^{-2}$ by $\text{tr}(X_{\text{scaled}}^{\top} X_{\text{scaled}})/p$ ($p = 4$) ensures dimensional consistency between the squared-seconds residual norm and the dimensionless relative parameter penalty. Because $p = 4$ and the objective is strictly convex, `fit_from_observations()` solves the constrained quadratic program **exactly** by enumerating all $2^4 = 16$ active-set faces of the lower-bound box $\theta \ge 0.25\theta_{\text{prior}}$, verifying primal feasibility and KKT optimality conditions. The fitted weights $\hat{\theta}$ are stored as the default calibrated weights of `InterpretableASTCostModel` and propagated directly through `compile_source()` and `server.py` into the generated runtime script.

**Online Pilot Calibration via Sample-Size-Weighted Shrinkage:** Static AST features cannot observe transient host-specific CPU clock scaling or memory bandwidth contention. At runtime, in `pilot_only` and `hybrid` modes, the coordinator first executes logical block $b = 0$ (of size $L = \min(L_{\text{logical}}, N)$) in-process, recording elapsed time $t_{\text{pilot}}$ and retaining its output as block $0$ of the simulation. Subtracting the fixed block invocation overhead $\tau_{\text{call}}(B) = \tau_{\text{serial}} \cdot (1.6\text{ if }B=2\text{ else }1.0)$ gives the empirical pilot rate $\hat{c}_{\text{pilot}} = \max\bigl(\epsilon, (t_{\text{pilot}} - \tau_{\text{call}}(B))/L\bigr)$. The hybrid estimate combines the static prior and pilot measurement via **sample-size-weighted linear shrinkage** (credibility weighting with prior equivalent sample size $N_0$, analogous to shrinkage estimators in Ledoit & Wolf, 2004):

$$\hat{c}_{\text{hybrid}} = (1 - \alpha)\,\hat{c}_{\text{AST}}(\mathcal{T}) + \alpha\,\hat{c}_{\text{pilot}}, \qquad \alpha = \text{clip}\!\left(\frac{L}{L + N_0},\; 0.15,\; 0.88\right)$$

with prior equivalent sample size $N_0 = 1,500$ (giving $\alpha = 5,000 / 6,500 \approx 0.7692$ for $L = 5,000$).

### 3.2. Unified Cost-Aware Adaptive Scheduler (Component B)

Both `compiler.py` (for static modes `fixed` and `ast_only` via `static_schedule_plan`) and `generator.py` (for online pilot-calibrated modes `pilot_only` and `hybrid` via `_plan_after_pilot`) invoke the unified `AdaptiveMonteCarloScheduler` (`src/montecarlo_dsl/scheduler.py`).

Given $B_{\text{rem}}$ remaining logical blocks ($N_{\text{rem}}$ iterations) and calibrated per-sample cost $\hat{c}$, let $W_{\text{rem}} = N_{\text{rem}}\,\hat{c}$ be the remaining numerical work. Each sample requires $m_{\text{sample}} = 8\,\bigl(N_{\text{vars}} + 3B + 2\mathbb{I}_{B=2}\bigr)$ bytes of active `float64` working arrays. Under a per-task working memory budget $M_{\text{budget}} = 32\text{ MB}$, at most $k_{\max} = \max\bigl(1, \min(B_{\text{rem}}, \lfloor M_{\text{budget}} / (L \cdot m_{\text{sample}}) \rfloor)\bigr)$ logical blocks may be grouped into one physical task.

`AdaptiveMonteCarloScheduler` compares two execution regimes:

1. **In-Process Serial Execution Schedule ($w = 1$)**: Groups remaining blocks into $T_1 \le 8$ coarse physical tasks ($k_1 = \min(k_{\max}, \lceil B_{\text{rem}} / T_1 \rceil)$) executed directly in the coordinator process, completely avoiding `ProcessPoolExecutor` creation, worker process memory duplication, and IPC pipe serialization:
   $$\hat{T}_{\text{serial}}(1, k_1) = W_{\text{rem}} + \left\lceil \frac{B_{\text{rem}}}{k_1} \right\rceil \tau_{\text{serial}}$$
2. **Multiprocessing Schedule ($w \in \{2, \dots, \min(W_{\max}, C_{\text{CPU}}, B_{\text{rem}})\}$)**: Targets $T_w = \min(B_{\text{rem}}, 4w)$ tasks ($k_w = \min(k_{\max}, \max(1, \lfloor B_{\text{rem}} / T_w \rfloor))$) with parallel scaling factor $\eta(w) = \max(0.55, 1 - 0.08(w - 1))$ and tail load-imbalance penalty:
   $$\hat{T}_{\text{parallel}}(w, k_w) = \tau_{\text{pool}} + \frac{W_{\text{rem}}}{w \cdot \eta(w)} + \left\lceil \frac{B_{\text{rem}}}{k_w} \right\rceil \tau_{\text{ipc}} + 0.25\,(k_w \cdot L \cdot \hat{c})$$

Multiprocessing ($w^* > 1$) is selected if and only if $\hat{T}_{\text{parallel}}(w^*, k_{w^*}) \cdot 1.12 < \hat{T}_{\text{serial}}(1, k_1)$. When $w^* > 1$, the final $2w^*$ blocks use halved task granularity $\max(1, \lfloor k_{w^*}/2 \rfloor)$ to reduce worker tail idle time.

### 3.3. Schedule-Independent Reproducibility and Dual Progress/Canonical Accumulators (Component C)

To ensure that any physical task partitioning produces identical final numerical outputs while maintaining exact consistency on every intermediate `batch` progress event:

1. **Logical Block Partition**: The iteration space $[0, N)$ is partitioned into $B = \lceil N / L \rceil$ canonical logical blocks, where block $b \in \{0, \dots, B-1\}$ covers $[bL, \min((b+1)L, N))$ of length $n_b$.
2. **Counter-Based PRNG Addressing**: Within logical block $b$, random variable $v \in \{0, \dots, K-1\}$ is sampled using an independent `Philox` generator:
   $$\text{RNG}(b, v) = \text{default\_rng}\!\bigl(\text{Philox}(\text{SeedSequence}([\text{MASTER\_SEED}, b, v]))\bigr)$$
3. **Dual Progress vs. Canonical State Separation**:
   - **Physical-Task Progress Accumulator (`stats_state`, `progress_sketch`, `progress_corr`)**: Updated exclusively from the completed physical task's own slice results (`result["branches"]` and `result["paired"]`). When a logical block is split across multiple physical tasks (e.g., when `batch_size < logical_block_size` or unaligned task boundaries are used) and tasks finish out of order (`as_completed`, `reverse`, or `shuffled`), every emitted `batch` progress event is guaranteed to satisfy `histogram.total_count == valid_results` and `valid_results + discarded_results == processed_iterations * BRANCH_COUNT`.
   - **Canonical Logical-Block Accumulator (`canonical_stats`, `canonical_sketch`, `corr_sum/corr_comp`)**: Tracks sample coverage `block_covered_samples[b]` for each logical block $b$. Once all $n_b$ candidate samples of logical block $b$ have been covered, block $b$'s summary is admitted into the canonical frontier and reduced in strictly increasing index order $b = 0, 1, \dots, B-1$ to produce the terminal `complete` event.

### 3.4. Asymptotically Bounded $O(1)$ Coordinator Memory and Dual Memory Instrumentation

In v1.2.0, retaining all raw arrays in `all_chunks` required $O(N)$ memory, and storing one paired correlation per logical block in `paired_state["correlations"][b]` required $O(B) = O(N/L)$ memory.

To achieve **strictly bounded $O(K_{\max}) = O(1)$ coordinator payload memory** as $N \to \infty$ across both single-branch and paired ($\pm$) models, `BoundedStreamingHistogram` (`src/montecarlo_dsl/statistics.py`, injected directly into `generator.py` via `inspect.getsource` so the statistical core and generated runtime execute the exact same code) implements **contiguous-frontier equal-mass centroid compaction**:

1. **Per-Block Equal-Mass Centroid Summary (`BlockHistogramSummary.from_array`)**: For $N > 65,536$ in `bounded` mode, each logical block $b$ sorts its $n_b$ finite values. If the block has $\le 256$ unique values (such as discrete distributions `\distrib`), it stores the exact unique support values and their integer frequencies with zero binning loss. Otherwise, it preserves the exact block extrema $(\min_b, 1)$ and $(\max_b, 1)$ and partitions the interior $n_b - 2$ sorted values into `FINE_HISTOGRAM_BINS - 2 = 254` equal-count slices, recording each slice's exact sample centroid $\bar{c}_{b,j}$ and integer weight $w_{b,j}$ such that $\sum_j w_{b,j} = n_b$.
2. **Contiguous Frontier Folding and Deletion (`_advance_state_frontier` and `_advance_paired_frontier`)**: The coordinator maintains pointers `next_canonical_block = 0` and `next_corr_block = 0`:
   - Whenever `next_canonical_block` is present in `batch_stats`, its Welford state is merged into `canonical_stats` and immediately popped (`batch_stats.pop(b)`).
   - Inside `BoundedStreamingHistogram`, `_advance_contiguous_frontier` pops `_pending_blocks.pop(b)`, appends its centroids and weights to `(_merged_centers, _merged_weights)`, and whenever `|_merged_centers| > 2 K_{\max}` ($K_{\max} = 2,048$), `compact_weighted_sketch` coalesces duplicate centers and partitions the cumulative weight distribution into $K_{\max} = 2,048$ equal-mass centroids (`32 KB`), preserving exact endpoints and exact total integer weight $\sum W = n_{\text{valid}}$.
   - In paired ($\pm$) models, `_advance_paired_frontier` pops `paired_state["correlations"].pop(c_idx)` in canonical order $c_{\text{idx}} = 0, 1, \dots, B-1$ and accumulates the correlation into `(corr_sum, corr_comp, corr_count)` using **Neumaier (1974) compensated summation**, keeping `len(paired_state["correlations"]) == 0` ($O(1)$ memory).
3. **Dual Memory Instrumentation**: To prevent conflating internal Python/NumPy data-structure payload with operating-system process memory, the runtime records both:
   - **Retained Coordinator Payload Memory (`peak_retained_coordinator_bytes`, `retained_coordinator_payload_bytes`)**: Exact byte count of all active NumPy arrays and dictionaries retained in the coordinator (`canonical_sketch`, `progress_sketch`, `batch_stats`, `correlations`, `pending_logical_blocks`, plus one working block buffer), tracked at its maximum across all batch ingestion steps.
   - **Real OS Process and Worker Peak RSS (`coordinator_peak_rss_bytes`, `workers_peak_rss_bytes`, `aggregate_peak_rss_bytes`)**: Measured via `resource.getrusage(resource.RUSAGE_SELF).ru_maxrss` in the coordinator process and in every distinct worker PID spawned by `ProcessPoolExecutor`.

---

### 3.5. Auxiliary Component: IEEE-754 and `NaN`-Safe AST Optimizer

`ASTOptimizer` (`src/montecarlo_dsl/optimizer.py`) executes between semantic validation and cost extraction. It applies:
- **Exact Decimal Constant Folding**: Evaluates constant subtrees (`+`, `-`, `*`, `/`, `\frac`, `\sqrt`, integer powers `^`) in `Decimal` and folds them into `NumberLiteralNode` only if the result converts to a finite, non-underflowing `float64` (preserving `GEN001` and `GEN004`).
- **IEEE-754 Safe Algebraic Identities**: Eliminates unary plus (`+x -> x`), double negation (`-(-x) -> x`), additive zero (`x + 0 -> x`, `0 + x -> x`, `x - 0 -> x`, `0 - x -> -x`), multiplicative unity/negation (`1 * x -> x`, `(-1) * x -> -x`), division by $\pm 1$ (`x / 1 -> x`, `\frac{x}{1} -> x`), and unit exponent (`x^1 -> x`).
- **Safety Prohibitions**: It never rewrites `0 * x -> 0`, `x - x -> 0`, `x / x -> 1`, or `x^0 -> 1` on dynamic subtrees (which would mask `NaN` or $\pm\infty$ realizations required by `nonfinite_policy = discard_and_report`) and never reorders floating-point additions or multiplications.

### 4.2. Baseline Definitions and Experimental Protocol

In `benchmarks/run_v1_3_experiments.py`, Experiment 5 (AST cost model calibration on the 8 training models) runs first and passes the trained `InterpretableASTCostModel` directly into all subsequent runtime experiments (`compile_source(..., cost_model=fitted_model)`), ensuring that the cost model evaluated in RQ2 is the exact model driving the runtime scheduler in RQ3.

We separate two distinct baselines:
1. **Historical Frozen v1.2.0 Baseline (`v1.2.0_legacy_configuration_emulation`, Experiment 0)**: Executes the legacy v1.2.0 runtime behavior (`seed_strategy="batch_index"`, `memory_mode="retain_all"` with full sample retention, `scheduler_mode="fixed"`, `optimize=False`, `max_workers=2`).
2. **Internal v1.3.0 Fixed Baselines (`v1.3_fixed_w1`, `v1.3_fixed_w2`, `v1.3_fixed_w4`, Experiments 2 & 9)**: Execute the v1.3.0 runtime (`seed_strategy="philox_logical_block"`, `memory_mode="bounded"`) with fixed physical batch size (`25,000`) and fixed worker counts (`1, 2, 4`), isolating the specific effect of the adaptive scheduler (`v1.3_adaptive_hybrid`).

**Repetition Counts and Statistical Rigor**:
- **Confirmatory Performance & Historical Baseline Campaigns (Experiments 0 & 2)**: **30 measured repetitions** per configuration after warm-up runs.
- **Pilot Scalability Grid, Batch Adaptation, Cost Model Calibration, Compiler Optimization, and $4 \times 2$ Ablation Study (Experiments 2, 3, 5, 6, 9)**: **10 measured repetitions** per configuration.
- **Analytical Statistical Validation (Experiment 7)**: **25 independent deterministic seeds** per model ($100,000$ iterations per seed = $2.5 \times 10^6$ samples per model).
- **Confidence Intervals**: Primary latency metrics are reported using the **median** and **interquartile range (IQR)**, accompanied by **95% percentile-bootstrap confidence intervals** computed over `10,000` resamples (`BOOTSTRAP_SEED = 120026`; Efron & Tibshirani, 1994).

Tables 4A and 4B establish three findings:
1. **Asymptotically Constant $O(1)$ Retained Coordinator Payload Memory**: As $N$ increases 25-fold from $10^5$ to $2.5 \times 10^6$, `retain_all` payload memory grows linearly (`1.527 -> 19.867 MB` and `3.247 -> 30.755 MB`), whereas `bounded` payload memory remains flat at **`0.207–0.215 MB`** (`normal_mean`) and **`0.583–0.607 MB`** (`quadratic_pm`, including $O(1)$ paired correlation compaction), achieving a **98.1%–99.0% payload reduction** in-process and **97.8%–98.8% reduction** under 2-worker multiprocessing.
2. **Transparent Process vs. Worker RSS Accounting**: The baseline Python + NumPy runtime footprint in a fresh subprocess is `180.9 MB` (`in_process_w1`), while spawning a 2-worker `ProcessPoolExecutor` (`multiprocess_w2`) raises aggregate peak RSS across coordinator and workers to `258.9–265.6 MB`. Thus, we distinguish strictly between the 98%–99% reduction in *retained coordinator payload memory* and the 30%–51% reduction in *sum of per-process peak RSS* achieved when the adaptive scheduler selects in-process execution over multiprocessing.
3. **Sub-0.18% Quantile Fidelity Across Diverse Distributions and Paired Branches**: Equal-mass centroid compaction achieves **0.000% quantile error** on discrete step distributions (`discrete_mean`) and bounds maximum relative quantile error to **$\le 0.174\%$** across unimodal, multimodal (`multi_discrete_complex`), right-skewed (`normal_quadratic`), heavy-tailed polynomial (`heavy_polynomial_pm`), and paired (`plus`, `minus`, `paired_delta`) distributions.

## 6. Discussion

### 6.1. Why Cost-Aware Scheduling Avoids the Multiprocessing Penalty

A key insight from both the historical v1.2.0 benchmarks and our v1.3.0 ablation study is that in vectorized Python/NumPy simulations, multiprocessing is not universally beneficial. When a 5,000-sample logical block is evaluated via vectorized NumPy `ufuncs` in a single process, a single core can evaluate $10^6$ iterations in `206–595 ms`. Spawning a `ProcessPoolExecutor` and pickling 40 batch dictionaries across OS pipes in our measured Linux `x86_64` environment adds `120–180 ms` of pool startup and IPC serialization overhead and adds `80–180 MB` of worker process RSS. By combining the KKT-Ridge AST structural prior with the block-$0$ pilot measurement, `AdaptiveMonteCarloScheduler` detects when $W_{\text{rem}}$ is below the pool break-even threshold, executing serially in-process for $N \le 10^6$ and activating multiple workers only when total compute work amortizes pool overhead (as verified at $N = 10^7$).

### 6.2. Balancing Exactness and Bounded Coordinator Memory

Our contiguous-frontier compaction design makes an explicit, transparent engineering trade-off:
- Moments (`avg`, `var`, `std`, `mcse`), extrema (`min`, `max`), paired correlations (`correlation_plus_minus_mean`), and sample accounting (`count`, `valid_rate`, `discard_rate`, total histogram count) are reduced via exact or compensated algebraic recurrences (Welford, Chan–Golub–LeVeque, and Neumaier summation) and therefore incur **zero approximation error**.
- Order statistics (`p05`, `p50`, `p95`) cannot be computed exactly in $O(1)$ memory over a single pass for continuous distributions (Munro & Paterson, 1980). However, by maintaining a 2,048-point equal-mass centroid sketch (`BoundedStreamingHistogram`) and coalescing exact duplicate support values, discrete distributions with $\le 32$ support points incur **zero error**, and continuous unimodal, multimodal, skewed, heavy-tailed, and paired distributions incur $\le 0.174\%$ relative error while reducing retained coordinator payload memory from `19.9–30.8 MB` to `0.21–0.67 MB`.

## 7. Threats to Validity

1. **Internal Validity**: Operating-system jitter and background daemons can perturb wall-clock timings. We mitigated this threat by executing warm-up runs, using 30 repetitions for confirmatory comparisons and 10 repetitions for pilot/ablation cells, and reporting medians, IQRs, and 10,000-resample bootstrap 95% confidence intervals.
2. **Construct Validity**: In v1.3.0, we separated the historical comparison against `v1.2.0_legacy_configuration_emulation` (Table 2) from internal comparisons against `v1.3_fixed` (Section 5.3), unified `BoundedStreamingHistogram` and `AdaptiveMonteCarloScheduler` between the library and generated runtime, and reported both retained coordinator payload memory and OS process/worker peak RSS (Table 4A).
3. **External Validity and Hardware Scaling**: Experiments were conducted on a 2-logical-CPU Linux `x86_64` host. While this setting directly tests the scheduler's ability to prevent multiprocessing slowdowns and oversubscription (e.g., requesting 4 workers on 2 CPUs), scalability curves on many-core nodes (16–64 cores) will exhibit different parallel break-even points, which the online pilot block is designed to measure at runtime.
4. **Reproducibility Boundary**: Exact SHA-256 bitwise invariance holds for a fixed model, `MASTER_SEED`, `TOTAL_ITERATIONS`, `logical_block_size`, code version, Python/NumPy version, and CPU/OS architecture. Cross-platform bitwise identity across different CPU SIMD instruction sets or `libm` implementations is not claimed.

## 8. Conclusions and Future Work

This paper presented and evaluated an AST-and-pilot-guided adaptive execution scheduler with schedule-independent reproducibility for a Monte Carlo DSL. Returning to our four research questions:

- **Answer to RQ1**: Decoupling logical blocks (`logical_block_size = 5,000`) from physical tasks using counter-based `Philox` streams indexed by `(MASTER_SEED, logical_block_index, var_index)`, dual progress/canonical accumulators, and canonical logical-block reduction preserved **100% SHA-256 bitwise invariance** across 14 physical schedules varying worker counts, batch sizes, scheduler modes, and completion orders across all 6 tested models, while guaranteeing exact progress event invariants (`histogram.total_count == valid_results`).
- **Answer to RQ2**: Projecting AST features onto 4 interpretable composite structural indices ($\text{rank} = 4$, $\kappa_{\text{std}} = 3.4054$) calibrated via exact KKT-constrained Ridge regression yielded an out-of-sample static MAPE of **12.35%** (Spearman $\rho = 1.0000$), and combining it with the block-$0$ pilot execution via sample-size-weighted shrinkage reduced out-of-sample cost prediction MAPE to **5.55%** (median error **5.04%**, Pearson $r = 0.9899$, Spearman $\rho = 1.0000$).
- **Answer to RQ3**: Propagating the trained cost model into the unified runtime scheduler achieved **2.41x–5.17x speedups** at $N = 10^6$ (and **2.72x–5.70x** at $N = 10^5$) over the frozen v1.2.0 baseline and **1.16x–1.56x speedups** over internal v1.3.0 fixed scheduling at $N = 10^6$ (and **1.36x** parallel speedup at $N = 10^7$), while reducing sum of per-process peak RSS by **48.1%–51.8%** when in-process execution was selected.
- **Answer to RQ4**: Contiguous-frontier equal-mass centroid sketch compaction and Neumaier paired correlation folding bounded retained coordinator payload memory to **$O(1)$ (`0.207–0.667 MB`, a 97.8%–99.0% reduction at $N = 2.5 \times 10^6$)** across both in-process and multiprocessing modes while preserving exact moments, extrema, and paired correlations and bounding weighted quantile relative error to **$\le 0.174\%$** across 6 distribution families and 10 branches.

Future work will explore (1) anytime-valid sequential confidence sequences (Howard et al., 2021) to support statistically rigorous optional stopping with guaranteed coverage, and (2) variance-reduction primitives (antithetic variates and multilevel Monte Carlo; Giles, 2015) integrated with the logical-block counter hierarchy.
